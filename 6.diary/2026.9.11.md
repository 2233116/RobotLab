1. P 控制异常现象进一步确认

继续测试当前速度闭环控制。

目标速度设为 100 RPM，观察到：

- PWM 从 30% 开始逐步增加；
- 电机速度从 0 RPM 上升；
- 曾经稳定在约 99～100 RPM；
- 随后电机实际发生突然减速；
- Encoder 测得速度从约 100 RPM 突然下降到约 48 RPM，随后出现 0 RPM；
- 控制器检测到速度下降后继续增加 PWM；
- 电机重新启动并加速到约 126 RPM；
- 控制器随后逐渐降低 PWM；
- 类似的“稳定 → 突然掉速 → 控制器补偿 → 超调 → 再调整”现象再次出现。

用户肉眼确认：速度突然下降时，电机本身确实明显变慢，因此不是单纯的 Encoder 数值跳变。

2. 固定 PWM 对照实验

关闭 P 控制，在约 50% PWM 下固定运行。

Encoder 测速结果：

- 启动阶段：0 → 约72 → 约101 RPM；
- 稳定运行阶段长期保持在约 100 RPM；
- 大多数数据约为 100～101 RPM；
- 中间出现过一次约 90.6 RPM，随后立即恢复到约100 RPM。

说明：

«电机、Encoder 以及 ZK-BM1 在固定约50% PWM的工况下可以稳定运行。»

因此目前没有证据表明“50% PWM 本身就会导致电机突然掉速”。

3. 当前问题定位

目前重点从：

«Encoder 测速异常»

转向：

«ZK-BM1 在 PWM 动态变化/闭环工况下是否存在内部异常。»

ZK-BM1 之前曾经在第一次 P 控制真机实验中出现过明显发热并冒烟，因此目前应将其作为重点怀疑对象。

暂不直接断言 ZK-BM1 已损坏。

4. 驱动器更换方案

决定下一步不继续反复折腾 ZK-BM1，而采用另一种驱动器进行 A/B 对照。

优先使用之前已经成功驱动过该电机的 TB6612。

计划：

- 同一个 ESP32
- 同一个 JGB37-520 电机
- 同一个 Encoder
- 尽量保持控制程序不变
- 更换驱动器为 TB6612

目的：

«判断异常是否随着 ZK-BM1 被替换而消失。»

5. TB6612 供电方案

讨论了使用两节锂电池串联，即约 7.4V 标称、8.4V 满电的 2S 电源。

已知当前 TB6612 模块标称：

- 连续电流：1.2A
- 峰值电流：3.2A

确认需要关注的是电机实际工作电流，尤其是启动/堵转电流，而不是认为“电池能提供大电流，所以电机一定会获得大电流”。

ZK-BM1 动态工况异常排查

现象

在速度闭环控制中，电机能够达到目标速度附近，但运行过程中会突然实际掉速。

100 RPM 目标测试中曾出现：

"约100 RPM → 约48 RPM → 0 RPM"

掉速发生时，PWM 并没有提前大幅下降，且肉眼确认电机实际明显减速。

控制器随后根据增大的速度误差提高 PWM，使电机重新启动并出现超过目标速度的情况。

已完成的对照

固定约50% PWM运行时，电机能够长期稳定在约100 RPM附近。

因此：

- Encoder 基本能够稳定测速；
- 电机在该工况下可以稳定运行；
- ZK-BM1 在固定PWM工况下没有复现严重掉速；
- 当前异常更值得从“PWM动态变化/闭环工况下的驱动器行为”方向继续排查。

当前判断

ZK-BM1 是当前重点怀疑对象，但尚未证明其内部损坏。

由于该驱动器此前曾出现过发热和冒烟，因此不继续用它进行大量高强度闭环实验。

下一步验证

使用 TB6612 替代 ZK-BM1，尽量保持：

ESP32、电机、Encoder、控制程序和实验条件不变。

通过驱动器 A/B 对照判断异常是否与 ZK-BM1 有关。

注意

TB6612 当前模块标称连续电流1.2A、峰值3.2A。

使用2S电池时避免堵转及长时间大电流运行，并优先进行低风险验证。下一节点

RobotLab 下一步不是继续调 Kp。

而是：

> TB6612 替换 → 基础运行确认 → Encoder方向确认 → 使用现有 P 控制进行 A/B 对照。



如果 TB6612 下异常消失，再重点判断 ZK-BM1；如果异常仍然存在，再继续查其他环节。

今天确认的长期原则

1. 先用实验隔离变量，再修改控制算法。


2. 不要因为控制器出现异常，就默认算法有问题。


3. 固定工况正常 ≠ 动态工况一定正常。


4. 出现过冒烟的硬件，不应该靠反复实验硬撑到“彻底坏掉”再判断。


5. 控制系统排查应沿着“控制器 → 驱动器 → 电机 → 机械系统 → 传感器”逐层隔离。
