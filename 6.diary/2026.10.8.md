今日主题

PID 工程化：Integral Windup 与 Anti-Windup 真机验证。

今日完成

在已经完成 P、PI、D、固定控制周期、PID 模块化和 dt 工程化的基础上，继续学习 PID 在真实执行器存在输出限制时的问题。

理解了 Integral Windup 的产生原因：当目标速度超过电机实际能力时，PWM 已经达到最大值，但误差仍然推动输出继续增加。如果积分项继续累加，就会产生大量历史积分，导致之后目标改变时系统恢复变慢甚至产生明显过冲。

确定第一版 Anti-Windup 逻辑：

- PWM = +100 且 error > 0：停止积分累加。
- PWM = +100 且 error < 0：清空积分。
- PWM = -100 且 error < 0：停止积分累加。
- PWM = -100 且 error > 0：清空积分。
- PWM 未达到输出边界：正常积分。

同时理解了 PID 内部 "self.pwm" 的时序意义：当前周期的积分判断使用上一周期已经经过限幅的实际 PWM，本周期计算得到的新 PWM 会在计算完成后保存下来，供下一周期使用。

真机实验

设置目标速度为 200 RPM。电机在 PWM=100 时实际最高只能达到约 164 RPM。

实验中观察到：

- PWM 达到 100。
- 实际速度约 160～165 RPM。
- error 一直为正。
- integral_error 约为 22.4 后不再继续增长。

验证了“输出已经饱和且误差继续推动饱和方向时，积分被冻结”。

随后程序在 PWM=100 时将目标速度从 200 RPM 自动切换到 100 RPM。

此时实际速度仍约 165 RPM，error 变为负值，并且上一周期 PWM 为 100，因此 Anti-Windup 的积分释放条件被触发。

观察到：

- PWM 从 100 快速下降到约 33.5。
- integral_error 被清零。
- 电机速度随后从约 165 RPM 下降到目标附近。
- PID 重新建立积分。
- 最终速度稳定在约 98～102 RPM，PWM 约 42～45。

今日结论

第一版 Anti-Windup 已经通过真实硬件验证。

完整过程：

目标超过电机能力 → PWM 饱和 → 积分冻结 → 目标降低 → 误差反向 → 积分释放 → PWM下降 → PID重新建立积分 → 重新稳定。

这说明当前 PID 已经不仅能够进行基本闭环控制，也开始能够处理真实执行器的输出边界。

长期原则

1. 成熟方案先跑通，改进方案先对照验证；未经硬件验证，不替换基线。
2. 参数一次只改变一个主要变量。
3. 控制算法必须考虑真实执行器边界。
4. 积分项不是无限记忆，历史状态必须服从执行器当前能力。
5. 硬件故障沿执行链反向追踪：执行器实际表现 → 驱动器实际输出 → 驱动器输入 → MCU实际输出 → 软件状态 → 代码逻辑。
6. 不为了复杂而复杂，只有真实实验暴露出问题时才引入新的工程机制。
