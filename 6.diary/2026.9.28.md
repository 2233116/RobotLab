一、今日学习节点

PI 闭环控制真机实验

今天继续昨天已经搭好的 PI 控制程序，目标是验证：

P + I 是否能够在真机上消除 P 控制留下的稳态误差。

当前控制结构：

目标转速 target_speed ↓ error ↓ ┌────┴────┐ ↓ ↓ P I ↓ ↓ Kp×error Ki×∑error └────┬────┘ ↓ PWM = base_pwm + P + I ↓ Motor ↓ Encoder ↓ current_speed └────────→ error 

二、首先发现的代码问题

原程序中有：

previous_speed = None 

然后稳定性判断使用：

if previous_speed is not None: if abs(previous_speed - encoder.current_speed) <= 2: ... 

但之前程序没有在每次测速完成后更新 previous_speed。

也就是说：

previous_speed 

一直保持：

None 

所以：

if previous_speed is not None: 

实际上一直无法正常进入。

最终确认需要在每次新的测速结果产生后更新：

previous_speed = encoder.current_speed 

今天得到的认识

一个状态变量不能只是“定义出来”。

需要同时明确：

在哪里初始化 ↓ 什么时候更新 ↓ 什么时候读取 ↓ 它代表哪个时刻的状态 

previous_speed 的意义就是：

保存“上一次测速得到的速度”，用来和这一次的速度进行比较。

三、修复后 PI 正常运行

修复 previous_speed 后，PI 控制开始真正工作。

当前主要参数：

kp = 0.1 ki = 0.01 target_speed = 100 base_pwm = 50 

控制关系：

error = target_speed - current_speed integral_error += error P = kp * error I = ki * integral_error pwm = base_pwm + P + I 

同时设置：

integral_max = 500 integral_min = ... 

并限制 PWM：

0 <= pwm <= 100 

四、第一次 PI 实验：integral_min = -500

修复代码后，PI 开始工作。

实验过程中大致出现：

PWM ≈ 50 速度逐渐上升 ↓ 约 87 RPM ↓ 105 RPM ↓ 114 RPM ↓ 117~118 RPM 

当满足稳定条件后，PI 开始调整 PWM：

PWM 50 ↓ 约 48 ↓ 继续下降 ↓ 约 44 

但是由于：

integral_min = -500 

积分最终达到：

integral_error = -500 

于是：

I = Ki × integral_error = 0.01 × (-500) = -5 

因此积分项最多只能提供：

-5 PWM 

左右的修正。

最终速度大约仍然在：

106～108 RPM 

附近。

五、由实验理解积分限幅

这里真正重要的不是“500”这个数字本身，而是理解：

integral_error ↓ Ki ↓ I ↓ PWM 

例如：

integral_error = -500 Ki = 0.01 I = -5 

如果：

integral_error = -700 

那么：

I = -7 

如果：

integral_error = -1000 

那么：

I = -10 

因此：

积分限幅实际上限制了 I 项能够对 PWM 施加多大的修正。

这也是为什么 -500 时速度仍然偏高。

六、第二次实验：integral_min = -700

随后把积分下限从：

-500 

改成：

-700 

其他主要参数保持不变。

结果：

integral_error 继续向负方向累积 ↓ I 可以从 -5 继续向 -7 靠近 ↓ PWM 可以进一步降低 ↓ 速度进一步接近目标 100 RPM 

这个实验说明：

原来的 -500 确实限制了积分修正能力。

但此时仍然没有证明：

-700 就是正确的最终参数。

它只是说明：

放宽积分下限以后，当前系统可以继续利用积分项降低稳态误差。

七、第三次实验：integral_min = -1000

之后继续放宽：

integral_min = -1000 

实验中积分继续向负方向累积。

出现过：

integral_error ≈ -749.9 I ≈ -7.50 PWM ≈ 42.47 speed ≈ 100.27 RPM 

之后还出现：

integral_error ≈ -805.9 I ≈ -8.06 PWM ≈ 41.94 speed ≈ 100.04 RPM 

最后一段大约：

integral_error ≈ -816.5 I ≈ -8.16 PWM ≈ 41.78 speed ≈ 100.52 RPM 

整体速度已经能够稳定在：

100～102 RPM 

附近。

八、今天最重要的实验结论

今天通过真机数据验证了一个非常重要的控制概念：

P 控制

P：

P = Kp × error 

只看当前误差。

当系统达到：

error ≈ 0 

P 项自然也会：

P ≈ 0 

所以 P 本身可能留下稳态误差。

I 控制

I：

I = Ki × integral_error 

而：

integral_error += error 

它会保存过去的误差。

所以即使：

error → 0 

也不意味着：

integral_error → 0 

因此 I 可以继续提供一个持续的修正量。

今天的真机验证

实验实际上形成了：

P 控制存在稳态误差 ↓ 加入 I ↓ 积分不断累积 ↓ I 提供额外 PWM 修正 ↓ 稳态误差减小 

这不是只在公式里理解，而是已经在电机真机上观察到了。

九、稳定性判断机制

目前程序还有一个稳定性门控：

if abs(previous_speed - encoder.current_speed) <= 2: stable_count += 1 

连续满足条件达到 3 次后：

if stable_count == 3: stable_count = 2 

然后才允许 PI 更新。

Encoder 的测速窗口约：

0.2 s 

所以大致相当于：

3 × 0.2 s ≈ 0.6 s 

即：

连续约 0.6 秒观察到速度变化较小，才允许控制器进一步调整 PWM。

这样做的意义是避免电机速度还在明显变化的时候就频繁调整控制量。

十、一个已经确认的重要区别

这里的：

stable 

并不是：

“速度已经达到目标。”

它真正表示的是：

速度变化比较小。

例如：

目标 = 100 当前 = 0 

如果一直保持：

0 → 0 → 0 → 0 

那么它也可以满足：

abs(previous_speed - current_speed) <= 2 

因此：

stable = True 

但显然：

0 RPM ≠ 100 RPM 

所以：

稳定 ≠ 达到目标。

这是控制系统里非常重要的区别。

base_pwm = 50

十四、今天形成的长期工程原则

① 状态变量要关注完整生命周期

今天的：

previous_speed 

就是典型案例。

不能只问：

“这个变量定义了吗？”

还要问：

“它什么时候更新？保存的是哪一个时刻的数据？”

② 成熟方案先跑通，改进方案先对照验证

当前 Motor、Encoder、P/PI 都已经经过实际验证。

后续如果想优化控制结构：

先保留当前能工作的版本 ↓ 新方案单独实验 ↓ 两者对照 ↓ 真机验证 ↓ 再决定是否替换 

不要因为理论上更漂亮，就直接替换已经工作的基线。

③ 一次尽量只改变一个主要变量

今天：

-500 ↓ -700 ↓ -1000

积分允许范围变大 ↓ I 修正能力变强 ↓ 稳态误差进一步减小 

以后调 Kp、Ki、base_pwm 时继续采用这种方式。
