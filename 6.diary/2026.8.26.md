2. Encoder 当前设计

counts_per_rev 属于 Encoder 的配置知识

创建 Encoder 时提供固定配置

pulse_count 属于运行状态，不应该机械地在对象创建时初始化测速意义上的状态

update() 负责更新 Encoder 自身状态

on_pulse() 负责处理中断到来的编码器脉冲/状态变化

get_current_speed() 对外提供当前速度

测速窗口暂定约 200 ms

测速窗口结束后取出并清零 pulse_count

count 为 0 时速度为 0

临界区用于保护“读取 count + 清零 count”这一短操作


3. 今天新学的类设计

Encoder 如果负责直接提供输出轴速度，就必须利用电机轴 → 输出轴的机械传动关系

gear_ratio 描述的是机械传动关系，不是 Encoder 本身的物理特性

区分了：

from motor import Motor → 引入 Motor 类

Encoder(motor) → 给 Encoder 一个具体 Motor 对象


开始理解 Class 和 Instance 的区别

发现 Encoder 直接持有整个 Motor，可能为了一个 gear_ratio 而产生过强耦合

当前还没有最终决定解耦方案


4. 今天最重要的设计原则

> 谁拥有这个机械事实，谁负责保存它；谁需要这个信息，谁读取它；但不要为了一个信息而依赖整个对象
