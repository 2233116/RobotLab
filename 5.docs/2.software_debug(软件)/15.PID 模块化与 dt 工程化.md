PID 模块化与 dt 工程化

1. PID 模块化结构

PID 从主程序中独立出来，由 "PID" 类负责控制量计算。

当前接口：

"pid.update(current_speed, dt, target_speed)"

PID 内部持有：

- "kp"
- "ki"
- "kd"
- "integral_error"
- "previous_speed"
- 积分上下限

PID 外部提供：

- "current_speed"
- "dt"
- "target_speed"

其中：

- "current_speed" 是当前测速结果；
- "target_speed" 是外部控制目标；
- "dt" 是本次 PID 更新对应的时间间隔。

控制调度不由 PID 类负责，而由主程序负责。

2. 控制职责

当前模块职责：

Encoder

负责获得实际机械速度。

PID

负责根据当前速度、目标速度和时间间隔计算控制量。

Motor

负责将 PID 输出转换为实际 PWM 执行。

Main / Controller

负责组织模块、决定 PID 什么时候运行，并提供控制目标。

3. dt 的工程化

原始方式：

"pid.update(current_speed, 0.6, target_speed)"

其中 0.6 是人为假定的固定控制周期。

改进后的方式是在主程序中累计 Encoder 每次测速的实际 "elapsed_time"：

"time_count = time_count + encoder.elapsed_time"

当累计到 3 次 Encoder 更新后：

"dt = time_count"

再将该 "dt" 传给 PID：

"pid.update(current_speed, dt, target_speed)"

这样 "dt" 表示的是这一次 PID 控制周期实际经过的时间。

4. 固定周期与非固定周期

如果控制器由硬件定时器严格保证固定周期，例如：

10 ms → PID → 10 ms → PID → 10 ms → PID

那么 PID 可以使用固定的 "dt = 0.01 s"。

如果 PID 的执行间隔可能变化，则应使用实际经过的时间作为 "dt"。

因此：

«"dt" 是由控制系统的调度方式决定的，不存在 PID 必须自己计算或必须由外部传入的绝对规则。»

5. 当前真机验证

PID 模块化恢复基线启动方式后，真机运行稳定。

典型稳态：

- 目标速度：100 RPM
- 实际速度：约 98～102 RPM
- PWM：约 43～46
- 控制周期：约 0.6 s

当前参数：

- Kp = 0.25
- Ki = 0.3
- Kd = 0.05

该组参数属于当前硬件和实验条件下的已验证基线，并非通用最优参数。

6. 工程原则

成熟方案先跑通，改进方案先对照验证；未经硬件验证，不替换基线。

在 PID 模块化过程中，应保持原有控制参数、启动条件、控制周期等实验条件不变，避免多个变量同时变化导致无法判断问题来源。
