双电机独立 PID：配置与验证记录

1. 目的

记录 ESP32-WROOM-32 上双电机独立速度闭环的硬件映射、控制参数、模块职责、已验证结果和后续测试计划，作为底盘控制整合的基线。

遵循工程流程：

基线 → 对照 → 验证 → 修改

未经真机验证，不随意替换已验证的硬件映射、控制参数和控制流程。

3. PID 参数与更新方式

当前已验证的 PID 参数：

- "Kp = 0.25"
- "Ki = 0.3"
- "Kd = 0.05"

左右两侧分别使用独立的 PID 实例，不共享积分状态或历史状态。

Encoder 测速

- 编码器测速窗口约为 0.2 秒。
- "Encoder.update()" 在产生新的有效测速结果时返回 "True"。
- "current_speed" 表示最近一次有效测速得到的速度。
- "elapsed_time" 表示本次测速所对应的实际经过时间。

PID 更新

每侧累计三次有效测速更新后执行一次 PID 更新，并累计这三次更新对应的 "elapsed_time" 作为本次 PID 的 "dt"。

当前控制周期约为 0.6 秒，但应以实际累计时间为准，不应把它视为严格固定周期。

当前实现使用最近一次有效测速的 "current_speed" 进行 PID 更新，而不是将三次速度读数再取平均。这是现有基线的行为，后续修改应独立验证。

4. 双电机独立闭环的职责结构

当前控制系统分为以下模块。

Motor

负责将控制器输出用于电机驱动。

Encoder

负责计算对应电机的实际速度，并提供测速时间信息。

PID

负责根据当前速度、目标速度和实际 "dt" 计算控制量。

MotorController

负责单侧电机的控制调度，包括：

- 持有对应的 Motor、Encoder 和 PID 对象；
- 保存目标速度；
- 累计有效测速次数和实际经过时间；
- 决定何时执行 PID 更新；
- 将 PID 输出发送给对应电机；
- 在每次控制更新后清零本轮累计状态。

Main

负责创建左右两侧对象，并持续调用两侧控制器的 "update()"。

当前主循环结构：

while True:
    left_motorcontroller.update()
    right_motorcontroller.update()

主循环不会因为左右控制器在同一轮循环中被调用，就保证两侧的测速更新时间和 PID 更新时间完全同步。

目标转速| 100 RPM| 100 RPM
稳定转速范围| 约 99–101 RPM| 约 100–102 RPM

该结果表明，在当时的硬件连接、供电和控制条件下，双电机独立闭环能够将两侧速度控制在目标附近。

不同测试条件下，实际 PWM 和速度可能变化。因此，这些数值是历史实验基线，不是所有条件下都必须出现的固定值。

6. MotorController 封装记录

测试日期：2026-10-22

6.1 封装目的

将原本重复写在主程序中的单侧闭环控制流程封装到 "MotorController"，降低主程序中的重复逻辑，并明确左右两侧的控制状态归属。

当前控制器保存：

- "motor"
- "encoder"
- "pid"
- "target_speed"
- "control_count"
- "dt"
- "pwm"

6.2 当前更新流程

每次调用 "update()" 时：

1. 检查对应 Encoder 是否产生新的有效测速结果。
2. 有效更新到来后，增加 "control_count"。
3. 将该次 "elapsed_time" 累加到 "dt"。
4. 累计三次有效更新后，执行一次 PID。
5. 使用当前速度、累计时间和目标速度计算控制输出。
6. 将输出发送给对应电机。
7. 清零本轮的计数和时间累计。

左右两侧独立维护上述状态，不共享控制器内部计数或 PID 实例。

6.3 封装后的初步测试

目标速度设为 90 RPM 时，启动初期出现过约 79–164 RPM 的较大速度波动；随后多数读数收敛到约 88–94 RPM。

这一结果说明启动初期和稳定运行阶段应分别分析，但还不能作为完整的动态性能验收结果。

7. 高频打印问题排查

重构过程中，曾在主循环中高频打印速度、目标速度和 PWM 等变量。调试时观察到 PWM 输出偏大和速度读数重复的现象。

将不必要的高频打印移出紧密循环，并把打印放到实际执行 PID 更新的分支后，运行表现有所改善。

当前结论：

- 高频打印会增加系统运行负载，并可能影响执行时序。
- 速度变量在新测速结果产生前可能保持旧值。
- PWM 通常只在控制器执行更新时改变。
- 连续出现相同的速度或 PWM 值，不自动意味着编码器中断丢失。
- 现有测试不能证明高频 "print()" 一定导致编码器中断丢失。

后续如仍有异常，应进一步检查编码器信号、引脚映射、电源和程序执行时序，不应直接把所有异常归因于打印。

8. 下一阶段：动态响应测试

当前优先验证已运行的闭环控制器，而不是立即更换 PID 参数或控制结构。

测试步骤

1. 将目标速度设为 90 RPM，等待系统趋于稳定。
2. 将目标速度改为 60 RPM，记录左右两侧的速度和 PWM 变化。
3. 待系统趋于稳定后，将目标速度改为 120 RPM，再记录响应过程。

每个阶段记录：

- 目标速度；
- 左右侧实际速度；
- 左右侧 PWM；
- 目标值改变的时间点；
- 速度上升或下降的过程；
- 超调和稳定时间；
- 稳态误差及波动。

左右两侧应分别分析，因为它们的测速更新时间、负载和所需 PWM 可能不同。

测试注意事项

- 保持硬件连接与 PID 参数不变，先完成对照测试。
- 启动瞬态与稳态波动分开记录。
- 不根据单次测速值就认定控制器失稳。
- 发现 PWM 长时间饱和时，应及时停止并检查，不能长时间强行运行。
- 测试时让车轮离地，出现驱动板异常发热、异味或异常声响时立即断电。

10. 工程原则

1. 先保留能稳定运行的基线，再逐项验证改动。
2. 不因左右电机结构相似，就假设引脚、测速和控制表现完全相同。
3. 控制参数、硬件连接和调度方式尽量不要同时修改。
4. 日志只记录必要的控制事件，避免无意义的高频打印。
5. 观察到的相关性不等于已经证实的根因。
6. 用可重复的实验数据决定是否修改控制器。
