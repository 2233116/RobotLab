PID Anti-Windup 工程验证

1. 背景

当前单电机速度闭环已经完成 P、PI、D、固定控制周期、PID 模块化和 dt 工程化。

真实电机存在输出能力上限。当目标速度超过电机实际能力时，即使 PID 继续增加输出，电机速度也无法继续提高。

例如：

- 目标速度：200 RPM
- 最大 PWM：100
- 实际最大速度：约 164～165 RPM

此时误差仍然为正，但执行器已经无法继续增加输出。

如果积分项继续累加，就会产生 Integral Windup。

2. Windup 问题

正常情况下：

error → integral_error → I → PWM

当 PWM 已经达到上限后，如果 error 仍然推动 PWM 增大：

PWM = 100
error > 0
↓
integral_error继续增加
↓
I继续增加
↓
但PWM仍然只能100

这些无法真正作用于电机的积分历史会被保留下来。

当目标改变、误差反向后，这些历史积分仍然存在，会影响系统恢复过程。

3. 第一版 Anti-Windup

当前采用基于实际输出 PWM 和误差方向的简单策略。

正向饱和

if self.pwm == 100 and error > 0:
    self.integral_error = self.integral_error

含义：

输出已经达到正向最大值，同时误差仍然要求继续增加输出，因此停止积分累加。

正向饱和后误差反向

elif self.pwm == 100 and error < 0:
    self.integral_error = 0

含义：

输出原本处于正向饱和，但误差已经要求减少输出，因此快速释放之前积累的积分。

负向饱和

elif self.pwm == -100 and error < 0:
    self.integral_error = self.integral_error

负向饱和后误差反向

elif self.pwm == -100 and error > 0:
    self.integral_error = 0

非饱和状态

else:
    self.integral_error = self.integral_error + error * dt

随后仍然使用原有积分上下限进行保护。

4. PWM 状态的时序

PID 当前周期的计算顺序为：

读取 current_speed
↓
计算 error
↓
读取上一周期 self.pwm
↓
决定积分行为
↓
计算 P/I/D
↓
计算新的 PWM
↓
PWM限幅
↓
self.pwm = 实际限幅后的PWM
↓
等待下一次 update

因此 Anti-Windup 使用的是上一周期已经确定的实际输出。

这避免了在同一个计算周期中出现“先知道本周期 PWM，再决定本周期积分”的循环依赖。

5. 真机验证

实验第一阶段：

target = 200 RPM

电机实际只能达到约：

164～165 RPM

实验观察：

PWM = 100
error > 0
integral_error ≈ 22.4

随后多个控制周期中：

PWM = 100
integral_error ≈ 22.4

积分不再继续增长。

验证：

«正向输出饱和且误差继续推动饱和时，Anti-Windup 能够阻止积分继续累加。»

6. 误差反向验证

程序在检测到：

pwm == 100

后将：

target_speed = 100

此时实际速度约：

165 RPM

因此：

error = 100 - 165 < 0

上一周期：

self.pwm = 100

于是触发积分释放。

实验结果：

integral_error = 0
PWM ≈ 33.52

随后电机速度下降，并经过 PID 调节重新稳定到：

98～102 RPM

PWM 最终约：

42～45

7. 验证结论

当前第一版 Anti-Windup 已通过真实硬件验证。

验证内容包括：

- 输出饱和时停止积分增长。
- 误差反向时快速释放积分。
- 正负方向逻辑均有对应设计。
- 释放积分后系统能够重新进入正常闭环调节。
- 最终能够重新稳定在目标速度附近。

因此当前 Anti-Windup 可以作为后续 PID 工程化的基线实现。

8. 当前边界

当前实现属于第一版、简单、易验证的 Anti-Windup。

暂时不引入更复杂的：

- back-calculation
- tracking anti-windup
- 更复杂的积分条件组合
- 额外滤波

只有后续真机实验明确暴露问题时，再根据基线实验结果决定是否升级。

9. 工程原则

成熟方案先跑通，改进方案先对照验证；未经硬件验证，不替换基线。

Anti-Windup 的引入不是为了让 PID “看起来更高级”，而是因为真实电机的输出能力有限，实验明确暴露出了执行器饱和这一工程边界
