## 1. 调试背景

新版 P 控制在原有简单 P 的基础上加入：

- Base PWM
- 稳定性判断
- 稳定后再进行 P 调整
- 不稳定时保持当前 PWM
- PWM 上下限

核心控制关系：

`PWM = base_pwm + Kp × error`

其中：

`error = target_speed - current_speed`

控制器不是每次测速都修改 PWM，而是：

> 只有确认电机速度已经暂时稳定后，才允许进行下一次 PWM 调整。

## 2. 当前新版 P 的结构

主要变量：

```python
kp
target_speed
previous_speed
stable_count
base_pwm
pwm
error

稳定性判断：

if previous_speed is not None:
    if abs(previous_speed - encoder.current_speed) <= 2:
        stable_count += 1
        if stable_count == 3:
            stable_count = 2
            # 允许进行下一次 P 调整
    else:
        stable_count = 0

其中：

previous_speed = None 表示当前没有上一笔有效速度数据。

abs() 用于取得速度变化量的绝对值。

<= 2 表示相邻两次测速的速度变化不超过 2 RPM。

连续 3 次满足条件后认为速度已经暂时稳定。

stable_count = 2 使后续每出现一次稳定采样都可以再次触发稳定事件。

   ↙       ↘

            ↓
       Base + P

            ↓

            ↓

设计目的：

避免在电机尚未充分响应前连续修改 PWM。

4. 重要概念区分

稳定性

稳定性判断：

abs(current_speed - previous_speed) <= 2

表示：

> 速度变化是否足够小。



目标误差

error = target_speed - current_speed

表示：

> 当前速度距离目标速度还有多少。



两者不能混为一谈。

因此：

> 稳定 ≠ 达标。



例如电机稳定运行在 80 RPM，而目标为 50 RPM：

速度可以是稳定的；

但误差仍然是 -30 RPM；

P 仍然需要考虑调整 PWM。

之后出现：

关键现象：

> 速度下降过程中 PWM 基本保持在约 44.7，没有继续降低。



因此：

> 不能直接把这次停转解释为 P 控制把 PWM 降得太低。



尤其需要注意：

如果 P 真正通过持续降低 PWM 导致停转，应当看到 PWM 随着速度变化持续下降。

本次异常中并没有出现这种对应关系。

7. 当前结论

已确认

1. 当前新 ZK-BM1 在 PWM=45 下可以正常驱动电机。


2. PWM=45 可以使电机稳定运行在约 85～86 RPM。


3. Encoder 可以在稳定运行状态下持续得到合理的速度数据。


4. 此次固定 PWM 实验没有复现之前的掉速到 0。


5. 因此“PWM=45 必然导致停转”这一解释不成立。

9. 当前软件调试原则

原则一：一次只改变一个变量

不要同时修改：

Kp

Base PWM

稳定阈值

稳定次数

控制周期


否则无法判断是哪一个变化导致结果变化。

原则二：先建立基线，再测试控制器

固定 PWM 实验可以作为电机系统的基础基线。

只有基础运行稳定，才能更可靠地分析 P 控制行为。

原则三：不要把“测量结果”直接等同于“物理事实”

Encoder 输出的是：

> 测量到的速度。



当出现 0 RPM 时，需要区分：

> 电机真的停止



还是：

> Encoder 没有检测到脉冲。



原则四：控制器异常和被控对象异常要分开

如果：

PWM 改变
→ RPM 改变

需要分析控制器与系统响应。

如果：

PWM 不变
→ RPM 自发异常变化

则需要优先调查被控对象、驱动、电源、机械和测量链路。
