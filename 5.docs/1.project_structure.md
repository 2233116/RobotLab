RobotLab V1.0 工程目录规范

一、为什么要重新整理目录

最开始，我把很多代码都放在了 "code" 和 "experiments" 中。

后来发现，很多所谓的"实验"实际上已经不再是单独测试某个硬件，而是多个模块组合完成一个完整功能，例如：

- 三按键控制 LED
- 超声波 + 蜂鸣器报警
- RobotController 控制程序

这些已经属于小项目（Project），继续放在 "experiments" 中会导致目录越来越混乱。

因此，决定重新规划 RobotLab 的目录结构。

---

二、目录职责

modules

存放可以重复使用的模块。

特点：

- 一个模块负责一个功能。
- 可以被多个项目调用。
- 不负责整个项目流程。

例如：

- button.py
- led.py
- buzzer.py
- sonar.py
- motor.py
- controller.py（后续）

---

tests

存放模块测试程序。

作用：

验证模块是否工作正常。

例如：

- led_test.py
- sonar_test.py
- motor_test.py

测试完成后，一般不会作为项目运行程序。

---

projects

存放完整的小项目。

特点：

- 由多个模块组成。
- 有自己的运行入口（main.py）。
- 实现一个完整功能。

例如：

- 三按键控制 LED
- 超声波 + 蜂鸣器报警
- WiFi 小车（后续）

---

docs

存放项目文档。

包括：

- 工程目录规范
- 引脚映射
- 原理说明
- 控制理论笔记
- Bug 与踩坑记录
- 参考资料

---

hardware

存放硬件相关资料。

包括：

- BOM 元件清单
- 接线图
- 电路图
- 硬件购买记录

---

diary

记录每次开发过程。

主要记录：

- 今日完成
- 遇到的问题
- 解决方法
- 今日收获
- 下一步计划

用于记录真实的工程成长过程。

---

三、目录设计原则

RobotLab 的目录按照职责划分，而不是按照功能划分。

判断一个文件应该放在哪里，只需要问自己一个问题：

这个文件承担什么职责？

- 给机器人真正运行 → modules / projects
- 给开发者验证功能 → tests
- 用于记录工程知识 → docs
- 用于记录开发过程 → diary
- 用于保存硬件资料 → hardware

以后随着 RobotLab 不断升级（ESP32 → STM32 → ROS2），继续沿用这一套工程规范。
